# SentFund sample payroll data

Generated by `node scripts/generate-sample-payroll.mjs` (seed 20261109). Re-running it must reproduce the checksums below exactly; if they differ, the generator or Node version changed behaviour.

All records are synthetic: phones use the fictional UK range `+44 7700 900000`–`900999` (one unique number per row), emails use the reserved `example.com` domain, and the NEAR account IDs are not demo wallets. **Never release a live testnet payout from these files.** The live demo uses a separate 2–3 row file with real, token-registered testnet accounts.

## Files

| File | Format | Data rows | Purpose |
| --- | --- | --- | --- |
| `public/templates/sentfund-payroll-template-blank.csv` | CSV, header only | 0 | Blank template users fill in |
| `public/templates/sentfund-payroll-sample-1000.csv` | CSV (RFC 4180, UTF-8, CRLF, no BOM) | 1000 | Realistic import + review + reporting check (A03, A07) |
| `public/templates/sentfund-payroll-sample-1000.txt` | Tab-delimited TXT (UTF-8, CRLF) | 1000 | Same rows as the CSV, TXT import path |
| `public/templates/sentfund-payroll-uniform-1000.csv` | CSV | 1000 | Posting-mode reconciliation: 1,000 × 0.01 = exactly 10.00 |

Amounts are deliberately tiny, **0.01 to 0.10 tUSDC per row**, so a showcase stays within a small, faucet-friendly budget. The PRD's large-number example (1,000 × 1,000,000 = 1,000,000,000) is covered by unit tests of the money and reporting code, not by a file.

Headers (canonical order): `near_account_id,receiver_name,currency,amount,mobile_phone,email`

No duplicate wallets, no duplicate phones.
